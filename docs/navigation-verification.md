# Navigation 3 구현 및 검증

2026-10-13 · [Issue #17](https://github.com/TEAM-SIRU/EcoGuard-APP/issues/17) · `feature/#17-navigation`

## 구현 범위

- 앱 신규 실행: 시스템 스플래시 → 로그인 → 샘플 학생 홈. 로그인 화면에서 교사용 계정 안내로 이동해 시스템 뒤로가기 또는 로그아웃으로 돌아올 수 있다. 실제 DataGSM OAuth나 토큰을 발급하지 않는다.
- 인증 전·후 NavDisplay를 분리한다. 후속 리프레시 토큰 검증 결과로 시작 화면을 선택할 때 이 경계를 재사용한다.
- 홈·구역·기록·마이페이지에 독립 back stack을 사용한다. 탭 전환·재선택은 기록을 유지하고, 같은 목적지를 다시 열면 기존 엔트리까지 돌아간다.
- 모집 → 신청 → 결과, 촬영 안내 → 샘플 촬영 → 확인 → 제출 완료, 인증 결과 → 이의신청 → 완료·내역·결과를 연결한다.
- 완료된 입력·촬영 단계는 스택에서 제거한다. 재촬영은 기존 촬영 엔트리로 돌아가고, 이미 제출한 상태는 안내 시트를 연다.
- 알림은 유효한 대상 확인 후 읽음 처리하고 모집·공지·인증·이의신청 목적지로 이동한다. 공지는 목록과 텍스트 상세를 제공한다.
- 월 선택·로그아웃·회원탈퇴 다이얼로그와 인증 안내 시트는 NavKey 오버레이로 관리한다. 기존 UI를 재사용하며 창을 중복 생성하지 않는다.
- 샘플 입력·사진 개수는 기록별 draft로 저장한다. 같은 기록을 여러 탭에서 편집해도 화면과 제출이 동일한 draft를 사용한다.
- 로그아웃·샘플 회원탈퇴는 메인 구성과 샘플 상태를 폐기한다. 실제 계정 삭제 요청은 하지 않는다.

계측은 API 34 에뮬레이터에서 실행했다. 원래 설정인 1080×2340px/density 440/font 1.0으로 복원했다. 다이얼로그 캡처는 플랫폼 창 전환이 끝난 후 수집한다. 위 결과는 자동 픽셀 일치 판정이나 실기기 전체 호환성 보장이 아니다.

`StateRestorationTester`로 알림 상세·읽음 상태, 신청 입력, 월 선택, 탭별 이의신청 입력과 스택의 저장·복원을 확인했다. 실제 프로세스 종료 검증은 아래 기록을 참고한다.

## 의존성과 후속 작업

Navigation 3 runtime/ui 1.1.6, Serialization core 1.9.0, Kotlin Serialization 플러그인 2.2.10을 사용한다. Kotlin·SDK 설정과 앱 권한은 유지했다. 실제 전이 의존성에서 SavedState 1.4.0, NavigationEvent 1.1.2, Kotlin stdlib 2.2.10을 확인했다. AndroidX·Kotlin 공식 라이브러리를 사용하며 별도 취약점 스캐너 실행 결과를 주장하지 않는다.

동일 환경에서 임시 `dev` 빌드와 현재 Debug APK를 비교했다. 기존 45,382,326바이트, 변경 후 45,094,832바이트로 약 0.63% 감소했다. 이는 해당 Debug 빌드의 순 크기 비교이며, 릴리스 APK·다운로드 크기나 개별 라이브러리의 크기 비용을 뜻하지 않는다.

실제 OAuth·액세스/리프레시 토큰·서버 제출·카메라·계정 삭제·청소 알림 등록·이용안내는 후속 작업이다. 업로드 실패·인증 시간 종료·주말/방학·시간 외/카메라 권한 제한·이의신청 전송 실패는 실제 서버·기기·학교 일정 결과에서 진입하는 조건부 상태다. 샘플 정상 흐름에 임의의 실패나 테스트용 상태 선택 화면을 추가하지 않았다. 교사 관리자 웹 주소와 복사·공유 동작도 제품 정보 확정 후 연결한다. 예측 뒤로가기의 연속 제스처·취소와 실기기 검증은 미실행이다.

## 실제 프로세스 복원

실제 `MainActivity`에서 샘플 로그인 → 알림 → 공지 상세 → 홈 버튼으로 백그라운드 이동 → `adb shell am kill com.nativelap.ecoguard` → 앱 재실행을 수행했다. 종료 전·후 PID가 달라 실제 프로세스 교체를 확인했고, 로그인 화면이 아닌 기존 공지 상세가 복원됐다. 뒤로가기로 알림 목록과 홈에 순서대로 돌아왔다. 알림 읽음 및 입력 상태는 별도의 StateRestorationTester 계측에서 검증했다.

시스템 뒤로가기와 오버레이 기본 닫힘·확인 액션은 계측으로 확인했다. 예측 뒤로가기의 연속·취소 제스처는 별도 수동 검증 대상으로 남긴다.
